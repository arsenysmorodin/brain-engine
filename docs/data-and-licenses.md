| `data/purine-pk-references.json` | Сводные Cmax/Tmax/AUC и условия | Числовые ориентиры с исходными единицами/типом статистики |
| `data/purine-pk-curves.json` | Оцифрованные маркеры/оси/погрешности/пробелы | Не исходные записи участников |

| `scenarios/`, `scenes/` | Воспроизводимые сценарии/сцена | Демонстрационные параметры, не персональные наблюдения |

Собственные схематические капилляры/венозные полилинии строятся Rust-кодом `crates/neuro-app/src/brain/circulation/geometry.rs`. Они не выдаются за микроскопические данные BodyParts3D или реконструкцию конкретного человека.

## Повторный импорт атласа

Обычная сборка использует уже закоммиченные геометрию/метаданные. Для повторного импорта есть Rust examples `import_brain` и `import_vessels`; их входы, диапазоны официального ZIP, CRC и SHA-256 описаны в [brain-atlas.md](brain-atlas.md).

```sh
cargo run -p neuro-domain --example import_brain --locked
cargo run -p neuro-domain --example import_vessels --locked
```

Эти команды требуют предварительно подготовленного кеша `.local/brain-source/` по спецификации; они не являются установкой приложения. Импорт может использовать `curl` и сеть даже при кешированных Cargo-зависимостях. Сохраняйте официальные источники и проверяйте полученные хеши до коммита. Полный архив тела в Git не добавляйте.

## Обновление научного набора

Для новой записи нужны первоисточник, URL/DOI/PMID при наличии, вид/выборка/условия, исходные единицы, тип агрегации, дата и фактический статус чтения, ограничения и права. Не переводите `abstract_verified` в полный статус по одному успешному HTTP-ответу.

При оцифровке сохраните неизменённый исходный файл вне дистрибутива, его хеш, оси, пиксельные координаты, погрешность и причины исключения/BLQ. Пересчитайте отчёт CLI, убедитесь в согласованности встроенных результатов и исходных кривых, обновите метрики/документацию. Отдельно укажите, какие данные использовались для подбора, а какие — для проверки.
